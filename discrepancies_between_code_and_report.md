# Discrepancies / Mismatches Between the Codebase and the Final Report (Team-Facing)

This file lists likely discrepancies between what the **final FYDP report** claims/labels and what the **repository actually implements or names**, based on inspection of:
- `FYP REPORT FINAL.pdf` / `FYP REPORT FINAL (1).docx` (the narrative)
- repository structure and outputs (pipelines, CSVs, figure naming conventions)
- the existing team overview files

> Note: The repository evolves across multiple pipeline generations (`4_*`, `5_*`, `6_*`, `7_*`, `8_*`, `9_*`). The final report corresponds to the *final narrative pipeline*, but some repository folders reflect earlier iterations. Some discrepancies are therefore “documentation drift” rather than functional errors.

---

## 1) Project naming: “KSE-30” vs “KSE-30 fund flows proxy”

### Report
- The report consistently frames the study around **KSE-30** and “index fund flows”.
- It describes constructing an **aggregate sector fund flow** proxy from three funds.

### Codebase (likely)
- The repo contains multiple pipelines where the flow proxy may be named/aggregated differently (e.g., `total_fund_flow`).

### Discrepancy to watch
- If a figure/table caption says “KSE-30 fund flow” while the computed series is actually `AKD + NBP + NTI` derived, ensure team wording always calls it a **proxy**.

## 2) Figures numbering (report) vs figure filenames (repo)

### Report
- The report references figures such as **Figure 3.1–3.5**, **4.1–4.8**, **5.1–5.5**, **6.1–6.5**.

### Repo
- The repo uses a folder-based naming scheme such as:
  - `overview/figures/eda/E01_aum_trend.png`
  - `overview/figures/fund_flow/FF01_total_flow_predictions.png`
  - `overview/figures/garch/G01_returns_and_vol.png`
  - `overview/figures/efficiency/EF01_acf.png`
  - `overview/figures/rebalancing/R01_retention_probability.png`
  - `overview/figures/summary/SUMMARY_dashboard.png`

### Discrepancy to watch
- The mapping is not automatically enforced by the code; it is done by manual alignment during report writing.
- Risk: a team member can accidentally describe `FF01` while the report’s **Figure 4.5** corresponds to ARIMAX/VAR actual vs predicted.

✅ Action for team: use this mapping approach when presenting:
- Mention figure **caption number** from the report, but point to the **corresponding filename** in `overview/figures/*`.

## 5) Statistical metrics: R² negative vs what teams say “explains”

### Report
- Fund-flow forecasting shows **negative R²** out-of-sample.
- The report emphasizes **directional accuracy** as the operationally meaningful metric.

### Repo
- Output CSVs like `results_fund_flow.csv` exist and likely store RMSE/MAE/R² and directional accuracy.

### Discrepancy to watch
- Teams may mistakenly interpret negative R² as “model failure”, rather than “magnitude is hard; direction works”.

✅ Action: Use the report phrasing: emphasize directional utility, not point prediction.

- There is an efficiency results table (e.g., `results_efficiency.csv`) with fields such as:
